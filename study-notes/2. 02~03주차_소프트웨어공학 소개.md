## Section 01. 소프트웨어의 이해

### 소프트웨어란?

단순한 프로그램(소스 코드)을 넘어 개발 과정에서 산출되는 모든 것을 포함하는 포괄적 개념

- 소스 코드(source code)
- 자료구조, DB 구조, 테스트 결과 등 모든 산출물
- 각 단계마다 생산되는 문서
- 사용자 매뉴얼

### 소프트웨어 vs 하드웨어 특성 비교

| 구분 | 하드웨어(H/W) | 소프트웨어(S/W) |
|------|------------|--------------|
| 생산 방식 | 제조 (정해진 틀, 능력별 차이 근소) | 개발 (개인 능력별 결과물 차이 큼) |
| 노후화 | 부품이 닳고, 고장 빈도 증가, 기능 저하 | 닳지 않고, 고장 빈도 낮고, 기능 동일 |

### H/W 실패 곡선 (욕조 곡선)

초기 실패율 높음 → 오류 해결 → 오랜 기간 사용 → 주변 환경 문제(먼지, 진동) → 실패율 재증가

### S/W 실패 곡선 비교

- **이상적인 곡선**: 개발 완료 후 변경/환경 변화 없을 때. 초기 오류 해결 후 폐기될 때까지 낮은 실패율 유지
- **실제 곡선**: 기능 추가·수정 시 변경으로 인한 부작용 발생 → 실패율이 주기적으로 급격히 증가

### 소프트웨어 개발의 어려움

| 어려움 | 설명 | 소프트웨어 공학의 대응 |
|--------|------|----------------------|
| 개발 과정이 복잡하다 | 복잡하면 문제가 많이 발생 | 복잡함을 줄이는 방법과 기술 제시 |
| 참여 인력이 많다 | 의사소통 복잡, 협력 어려움, 인력 변동 | 팀 구성·관리의 효율적 방법 제시 |
| 개발 기간이 길다 | 진행 상황 파악 어렵고 비용 산정 곤란 | PMBOK 등 프로젝트 관리 지식체계 소개 |

- **H/W vs S/W 발전 속도 차이**: H/W는 검증된 부품 조립 방식, S/W는 처음부터 만드는 개발 방식 → 해결책: **CBD(Component Based Development) 개발 방법론**

## Section 02. 공학과 소프트웨어 공학의 이해

### 공학(Engineering)의 특성

- 과학적 지식을 활용하여 문제를 해결
- 제약 사항: 정해진 기간 + 주어진 비용

### 소프트웨어 공학의 정의

> 품질 좋은 소프트웨어를 경제적으로 개발하기 위해 계획을 세우고, 개발하며, 유지 및 관리하는 전 과정에서 **공학, 과학 및 수학적 원리와 방법을 적용**하여 필요한 이론과 기술 및 도구들에 관해 연구하는 학문

### 소프트웨어 공학의 목표

- 개발 과정에서의 **생산성 향상**
- **고품질 소프트웨어** 생산 → 사용자 만족

### SDLC (Software Development Life Cycle)

소프트웨어 개발 생명주기 — 계획 → 분석 → 설계 → 구현 → 테스트 → 유지보수

## Section 03. 소프트웨어 개발 단계 소개

### 개발 프로세스 6단계

| 단계 | 주요 내용 |
|------|----------|
| 1. 계획 | 비용 산정(COCOMO, FP), 일정 계획(WBS, CPM), 위험 관리 |
| 2. 요구분석 | 기존 시스템 문제 파악 → 요구사항 도출 → 다이어그램 작성, 최종 산출물: 요구분석명세서 |
| 3. 설계 | 분할과 정복, 추상화, 모듈화, 정보은닉 / 아키텍처, GoF 디자인 패턴, 응집도·결합도 |
| 4. 구현 | 프로그래밍 언어, 표준 코딩 규칙 |
| 5. 테스트 | 절차·분류 방법, 품질 특성별 테스트 |
| 6. 유지보수 | 수정·적응·기능보강·예방 유지보수 |

### 요구분석 표현 도구 (방법론별)

- **구조적 방법론**: DFD, DD, Mini Spec
- **정보공학 방법론**: E-R 다이어그램
- **객체지향 방법론**: UML 유스케이스 다이어그램

### WBS (Work Breakdown Structure)

프로젝트 목표 달성을 위해 전체 업무를 최하위 작업 패키지 단위로 계층화하여 세분화한 구조도

### 소프트웨어 개발 프로세스 모델 종류

- 주먹구구식 / 선형순차적(폭포수) / V 모델 / 진화적(프로토타입) / 나선형 / 단계적 개발 / 통합 프로세스(UP) / **애자일** 프로세스 모델

### 품질 관리 모델

- 제품 품질: ISO/IEC 9126
- 프로세스 품질: ISO/IEC 9000, ISO/IEC 12207, CMMI, SPICE

### 프로젝트 관리 - PMBOK 9가지 관점

형상 관리 포함, ① 통합 ② 범위 ③ 일정 ④ 비용 ⑤ 품질 ⑥ 인적자원 ⑦ 의사소통 ⑧ 위험 ⑨ 조달
